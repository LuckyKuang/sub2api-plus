# 聚合 API Key

聚合 Key 是独立新增的按量分组绑定方式。原有单组 Key、未分组 Key、Composite
分组及其可选统一端点转换继续使用原流程；旧 Key 不自动迁移。

## 配置与范围

在 API Key 页面选择“创建聚合 API Key”。默认“全部分组”动态包含当前用户有权绑定、
已启用、`subscription_type=standard` 的普通分组。“自定义分组”保存非空的固定选择，
不会自动加入新组。两种模式均排除 Composite 和订阅分组。

创建入口使用主题主色按钮。创建和编辑时，自定义选项和已选分组使用与普通 Key 相同的
平台图标与配色徽章，并显示倍率。所有已选分组名称完整换行显示，长名称不省略；
搜索和复选仍保留在同一个下拉菜单内，可连续选择或取消。失效分组保留文字提示。

请求时重新读取用户授权和分组状态。撤权、停用、删除或改为订阅的组立即退出候选；
自定义配置仍保留原 ID，编辑时可移除失效成员。空范围可保留 Key，但不能执行推理。
全部模式不保存创建时的组快照。

创建和编辑 API 使用 `group_binding_mode`：`single`、`all`、`custom`。
省略模式保持 `single`；`group_id=null` 的旧 Key 仍然是未分组 Key。
`custom` 使用正整数、无重复、非空的 `aggregate_group_ids`；`all` 的该数组必须为空。
聚合 Key 的 `group_id` 必须为空，不能启用 `conversion_enabled` 或设置
`default_client/default_endpoint`。现有单组与聚合类型之间不原地转换，创建另一把 Key 即可。
聚合 Key 可以在 `all` 和 `custom` 之间编辑切换。

迁移 `308_aggregate_api_keys.sql` 为旧记录提供 `single` 和空数组默认值。
自定义成员以 JSONB 数组与模式同列更新，保证原子性；当前授权与组有效性由服务校验，
删除组不改变 Key 的固定选择，也不能让该组继续参与。编辑仅更新显式配置列，
不覆盖并发累计的 `quota_used` 或金额窗口用量。

## 请求、模型与价格

先从当前范围找出允许公开模型且具有目标原生协议能力的组，再按 `sort_order`、ID
升序选择。能力来自持久化账号配置、模型映射、已缓存的上游模型元数据和维护的默认目录；
不在此步骤调度账号、探测供应商或刷新凭据。渠道映射及模型限制同样参与候选筛选。
未知别名需要账号或渠道映射/模型元数据，不能仅靠空模型映射把请求发给第一个平台。

选组只生成请求内的副本。随后沿用实际组的白名单、安全审计、账号调度、个人价格、
不可变计费证据、用户平台配额和 RPM/并发规则。费用从用户余额扣减，不消耗订阅额度。
Key 的总额度和 5 小时/日/周金额窗口跨组共享，用户全局限制同样共享。
日志记录真实 Key、实际组和实际账号，不生成虚拟统一倍率。

聚合请求使用模型支持的原生端点，不提供 Key 级统一转换。相同模型可以在不同组拥有
不同原生能力，因此端点也参与选组。审计拒绝、余额或额度不足、供应商故障均不会触发
新的跨组重试；原组的跨组降级在聚合请求中禁用。单组 Key 的原降级规则不变。

`GET /v1/models` 合并去重当前范围的原生模型；带 `client_version` 的列表仅包含原生
Responses 模型。`GET /v1beta/models` 仅合并原生 Gemini 模型。模型列表描述配置能力，
不承诺供应商此刻没有临时限流或故障。
管理接口 `GET /api/v1/keys/:id/native-access` 检查所有权，返回公开模型、端点及候选组 ID，
不返回凭据或账号 ID。“使用 Key”弹窗使用此接口展示真实原生端点及可选分组请求头。
Gemini 普通组保留已启用混合调度的 Antigravity 原生 Gemini 账号；不因此启用协议转换。

## 会话与资源

成功路由响应包含 `X-Composite-Group-ID`。客户端可以在后续请求中以同名请求头固定分组；
服务端仍检查该组属于当前授权范围并支持请求的模型及端点。

多组范围的续会话、WebSocket 握手、资源读取/修改/删除，以及缺少模型的新建操作，
必须提供该请求头。范围只有一组时可直接确定该组。模型无法明确或缺少必要分组时返回
明确的 400 错误，绝不猜测资源所属组。请求头只选择组，不授予资源权限：
原有 Files、Gemini cache、异步任务、续会话及账号归属校验继续执行。
调用者应从首次请求开始固定同一分组，保持组内原有账号亲和性。WebSocket 后续每轮
在审计之前重新检查该组授权、原生能力与当前政策，计费使用该轮的最新组价格；撤权、
组类型/平台改变或失效时关闭连接，不改选其他组。

示例（将 `GROUP_ID` 替换为候选组 ID，Key 从安全环境变量注入）：

```bash
curl "$BASE_URL/v1/responses" \
  -H "Authorization: Bearer $API_KEY" \
  -H "X-Composite-Group-ID: $GROUP_ID" \
  -H 'Content-Type: application/json' \
  --data '{"model":"MODEL","input":"Hello"}'
```

## 安全与缓存

认证快照记录模式和自定义 ID，变更会清理认证缓存；快照版本升级后旧缓存回源。
动态用户授权、组政策及能力读取发生在每次请求，不能被 Key 快照冻结。
只读选组发生在 canonical audit 之前，以确定正确的组审计作用域；账号选择、计费预留、
RPM/并发获取和供应商写入仍在审计之后。聚合 Key 的最后使用时间也只在审计通过后更新。
出站身份沿用实际凭据所有者及既定优先级，新增配置不参与身份选择。

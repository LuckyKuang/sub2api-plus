# 用户协助只读视图

管理员在账户选择器中选择其他用户后，使用该用户的原个人页面、菜单、功能开关和读取逻辑。协助对象独立于登录身份；管理员的 JWT、刷新令牌和持久化登录资料始终属于管理员。

## 页面与数据

协助页面复用仪表盘、API 密钥、异步图片、批量图片、使用记录、可用渠道、渠道状态、订阅、购买、订单、兑换、邀请、个人资料和用户自定义页面。渠道监控沿用现有 V1/V2/V3 模式和用户权限。

API 密钥沿用用户 DTO，返回完整密钥、完整 IP 白名单/黑名单、分组、限额和用量。保留用户页面原有的掩码/显示、复制、真实密钥配置示例和使用指南。个人资料沿用用户 DTO 和认证信息组装逻辑，包含用户自己可见的身份绑定、TOTP 状态与验证方式、Passkey 列表、头像和余额通知设置。密码哈希、TOTP 种子、OAuth 登录令牌等用户页面原本不返回的内部认证材料仍不属于该视图。

筛选、分页、图表、导出、查看、复制和已有图片下载保持可用。编辑弹窗可用于查看现有配置，但配置字段只读、提交按钮禁用。新增、修改、删除、启停密钥、修改分组、重置用量、图片提交/重试/取消、购买、兑换、退款和认证绑定等写操作禁用。

自定义 Markdown 与公开嵌入页面复用原页面。需要用户登录凭证的外部嵌入站点不获得管理员 JWT，也不创建用户会话；其外部登录状态不在本系统的协助范围内。

## 接口与身份

协助读取位于 `/api/v1/admin/support/users/:user_id`，由现有管理员认证和合规中间件保护。目标用户必须存在且未删除；允许协助已停用用户。路由逐项声明且仅注册 GET，直接复用普通用户读取 handler。

`GetAuthSubjectFromContext` 始终返回真实管理员。仅 GET 读取 handler 使用独立、经过管理员及目标校验的 `GetReadSubjectFromContext` / `GetReadUserRoleFromContext`。所有写 handler 保持真实认证身份。

`/usage/dashboard/api-keys-usage` 的批量查询在协助模式下改为 GET 查询参数，继续校验目标用户对密钥的所有权。其他业务 POST/PUT/PATCH/DELETE 不发送；登出仍作用于管理员本人。

图片读取使用管理员 JWT 和 `api_key_id`，后端校验密钥属于目标用户，再沿用用户和密钥双重所有权检查。协助下载不标记批量图片为“已下载”，不创建任务、不修复执行状态、不调用推理接口。使用指南的模型目录读取复用现有网关 GET 分发与上游身份规则。敏感响应禁止缓存。

每个协助 GET 记录 `admin.support.read` 管理审计，包括真实管理员、目标用户路由参数、资源路径和结果。审计不采集响应体，查询参数继续脱敏，不记录返回的完整密钥或认证资料。

## 切换与审计

进入、退出、切换目标或替换登录身份时递增读取代次，清理目标资料、订阅、图片访问能力、公告和内存中的图片密钥映射；旧响应不能覆盖新对象，进行中的图片请求取消。用户页内部跳转保持目标范围，选择本人或退出协助恢复管理员视图。

建议在 web 中逐项核对：

- API 密钥 > 完整密钥显示/复制、使用指南、配置示例、分组及 IP 规则、只读编辑弹窗。
- 个人资料 > 用户信息、身份绑定、TOTP、Passkey、头像、余额通知设置。
- 使用记录 > 筛选、分页、图表、详情和导出。
- 图片任务 > 密钥切换、列表/详情、预览和下载；下载后用户原任务状态保持不变。
- 可用渠道、渠道状态、订阅和订单 > 与目标用户可见信息一致。
- 连续切换两个用户并退出 > 页面、余额、公告及任务不残留前一个用户的数据，管理员登录身份保持不变。

回归覆盖独立读取身份、完整密钥/认证信息响应一致性、跨用户/密钥越权、写路由缺失、真实管理员审计、下载状态不变，以及前端读取映射、请求取消和只读交互。检查命令与容器要求见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
